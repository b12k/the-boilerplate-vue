# Пункт 4: ограниченные подключения Redis

Базовый коммит: a401032. Реализация и проверки завершены 9 октября 2026. Пользователь подтвердил ревью и отдельный коммит 9 октября 2026. Коммит: 0475943.

REDIS_CONNECTION_RETRIES — необязательное целое число от нуля, по умолчанию 5. При старте это первая попытка плюс пять повторных: всего шесть подключений. После потери ready-соединения — до пяти попыток восстановления. Значение 0 разрешает только первоначальное подключение. После успешного подключения бюджет следующего обрыва начинается заново.

CacheService запускает подключение в фоне. HTTP не ждёт его завершения. Пока клиент не ready, чтение даёт промах, запись пропускается, pending не захватывается; приложение продолжает обычный SSR.

Вся попытка подключения ограничена 1000 мс, включая TCP и AUTH/handshake. После неудачи до следующей попытки проходит 1000 мс. Встроенный reconnect отключён: последовательным циклом управляет RedisCache. Для каждой попытки создаётся клиент; после отказа он уничтожается. Старый клиент после разрыва ready-соединения также уничтожается. Watchdog отменяется при завершении попытки; позднее отклонение Promise обработано.

Логи содержат номер попытки, общий предел и причину отказа. После исчерпания лимита новых попыток нет до перезапуска процесса. SSR остаётся доступен; автоматическое восстановление кеша возможно, если Redis вернулся до исчерпания лимита.

Повторные циклы восстановления не оставили открытых старых сокетов. После исчерпания приложение оставалось живым, необработанных отклонений Promise в логах нет. В source и dist проверены значения по умолчанию, 0/2/5 и отказ схемы для -1, 1.5 и нечислового значения.

Первый прогон выявил ошибку тестового proxy: тихое соединение не читало входящие байты и не наблюдало FIN. Proxy исправлен, сценарий закрытия сокетов пройден. Один запуск тестового контейнера превысил 15-секундный предел fixture; созданный контейнер удалён, предел команды увеличен до 45 секунд. Финальная матрица прошла полностью.

pnpm check и git diff --check пройдены. Полный UI QA не повторялся: оформление не менялось. Поведение общих Redis-механизмов проверялось в Docker по согласованному сокращённому плану.

## Границы пункта

Тайм-ауты команд уже подключённого Redis относятся к пунктам 5 и 15 и ещё не реализованы. Тайм-аут подключения не ограничивает GET/SET/EVAL готового соединения. SSR response budget и graceful shutdown также остаются отдельными пунктами.

Длительность HTTP выше — измерение тестовых страниц на этом окружении, а не бюджет всех SSR. Таймер Node может сработать позднее при блокировке event loop.

Профильные fixtures и JSON-результаты находятся в папке артефактов: redis-proxy-4.mjs, check-redis-retries-4.mjs, check-retry-env-4.mjs, fix-4-redis-retries.json, fix-4-env-source/dist.json и recheck-fix-4-dev/local/docker.json. Тестовые контейнеры удалены; dev восстановлен. Для Windows использован отдельный SWC cache root процесса агента без изменений конфигурации проекта.
