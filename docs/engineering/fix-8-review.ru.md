# Пункт 8: SSR deadline и упрощение записи кеша

Базовый коммит: 3509fb4. Реализация и проверки завершены 9 октября 2026. Пользователь подтвердил отдельный коммит 9 октября 2026. Коммит: 2080a76.

SSR middleware использует SSR_RESPONSE_BUDGET_MS, по умолчанию 30000 мс. Бюджет начинается при входе в middleware и включает загрузку assets, чтение кеша, prefetch, render и подготовку HTML/state. После превышения обычный error middleware возвращает HTTP 500 и пишет структурированный SSR_RESPONSE_TIMEOUT с requestId, route, budgetMs и elapsedMs.

Deadline вынесен в utility. Таймер отменяется после завершения ожидания. Проверки прошедшего времени также стоят после await и перед передачей HTML в response.send: синхронная работа может задержать таймер, но её просроченный результат не отправляется. Позднее завершение или отклонение renderer не вызывает второй ответ и не публикует HTML в кеш.

Запрос с подтверждённым pending запускает его удаление в фоне. Ответ 500 не ждёт Redis. Позднее подтверждение SET NX также приводит к очистке. Удаление атомарно проверяет строку pending; готовая запись сохраняется. Без подтверждения установки запрос не удаляет pending. При недоступности Redis остаётся страховочный TTL.

Согласованное упрощение CacheService выполнено: готовые HTML и critical CSS записываются обычным SET с TTL в секундах. SET NX, обычная строка pending и локальное подтверждение установки сохраняются. Debug refresh использует встроенный SET IFEQ с PX TTL; удаление только pending — встроенный DELEX IFEQ. Lua удалён. UUID и привязки к владельцу нет.

По запросу пользователя 9 октября Redis обновлён до 8.10.2: в Compose закреплён redis:8.10.2-alpine и обновлён действующий контейнер cache. Существующий volume the-boilerplate-vue_redis сохранён. npm-клиент redis 6.3.0 уже актуален и поддерживает команды. Внешний Redis должен быть не ниже 8.4, где появились [условные SET и DELEX](https://github.com/redis/node-redis).

## Границы пункта

Deadline прекращает ожидание и дальнейшую обработку результата. Отмена поддерживаемых API-операций и реакция на отключение клиента реализуются пунктом 9. Синхронный JavaScript нельзя принудительно остановить таймером в основном потоке.

После передачи HTML в response.send запись кеша и расчёт CSS не входят в HTTP budget. CSS сохраняет собственный бюджет из пункта 1; перенос в Piscina — пункт 13. Уже отправленная команда Redis может завершиться позднее; ограничения ожидания SET и DELEX относятся к пункту 15. Изменение оформления обычной страницы 500 остаётся пунктом 29.
