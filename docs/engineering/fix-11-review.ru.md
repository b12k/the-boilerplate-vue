# Пункт 11: DEBUG из режима приложения

База: 408bcd3. Статус: реализовано, проверено и подтверждено пользователем 10 октября 2026 для отдельного коммита.

## Изменение

DEBUG удалён из .env, .env.example, env-defaults.ts и входной схемы. В env.ts он вычисляется как !IS_PROD: development включает диагностику автоматически, production включает её для текущего запроса только по правильному DEBUG_ON_KEY. Старая переменная DEBUG больше не влияет на режим.

DEBUG_ON_KEY остаётся опциональным UUID. Отсутствие переменной выключает доступ по ключу; пустое или невалидное заданное значение отклоняется при запуске. Полная HTML-диагностика и доверенные ENV_OVERRIDES сохранены; ротация ключа и маскирование логов относятся к другим решениям.

При проверке холодного render-cache обнаружено, что ключ из query сохранялся в context.query и context.url, а затем попадал в обычный HTML через context.cached. Теперь доступ проверяется по исходному запросу, после чего DEBUG_ON_KEY исключается из сериализуемых query и URL. Остальные query-параметры сохраняются.

## Проверки

pnpm check и git diff --check проходят. Для TypeScript source, local dist и свежего Docker dist проверены 32 контекста: development/production, отсутствующий/правильный настроенный ключ, cookie/header/query, правильный/неправильный переданный ключ. Пустой и невалидный настроенный ключ отклоняется в обоих режимах. Также проверены refresh-флаги, сохранение обычного query и исключение DEBUG_ON_KEY из сериализуемого query и URL.

| Режим            | Результат                                                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| pnpm dev         | Диагностика включена без ключа; девять HTTP-маршрутов и ассеты; hydration и home → about → home; консоль neo чистая                                      |
| pnpm start:local | Свежая сборка; без ключа обычный HTML; девять HTTP-маршрутов и ассеты; тот же browser smoke; консоль чистая                                              |
| Docker           | Свежий codex-bpv-debug-mode:20261010; production с отсутствующим и правильным ключом, отказ запуска с пустым ключом; HTTP/browser smoke и чистая консоль |

В Docker десять HTTP-сценариев с настроенным ключом подтверждают доступ через cookie/header/query, отсутствие диагностики при неверном или отсутствующем ключе, изоляцию debug и обычных cache-hit ответов. Отдельно проверен debug-запрос по холодному кешу: следующий обычный cache hit не содержит ключа.

Неверный ключ не разрешает ENV_OVERRIDES. Верный ключ с недоступным API вызывает диагностический 500; следующий обычный запрос получает 200 без overrides. В neo также проверены debug query → обычный запрос и сохранение foo=kept.

SWC в агентском Windows-окружении использует ранее согласованный SWC_NATIVE_BINDING_CACHE. Существующее предупреждение DEP0205 относится к SWC register. После проверок dev оставлен работающим; временные тестовые контейнеры удалены.
