# Пункт 19: HTTP methods для SSR

Статус: пользователь подтвердил отдельный коммит 10 октября 2026. Пункт 18 подтверждён пользователем и закоммичен: 86221d2.

## Изменение

В server.ts SSR зарегистрирован через app.get. Express автоматически обрабатывает HEAD тем же обработчиком и возвращает ответ без тела; отдельной HEAD-логики нет.

Общий список ssrPaths используется для GET и следующего app.all. Шаблон /en{/*ssrPath} принимает /en, /en/ и вложенные пути. Query не влияет на сопоставление маршрута; контекст сохраняет параметры. Похожие префиксы /english и /enough не совпадают.

Остальные методы на этих HTML-маршрутах получают 405, Allow: GET, HEAD и короткое стандартное сообщение Method Not Allowed. SSR и его операции кеша не запускаются. Health, API, static и языковой redirect сохраняют положение до этого ограничения.

## Границы изменения

Код изменён только в server.ts. Полные проверки оформления, Piscina и отказов Redis не повторялись: их реализация не затронута. Пункты 20 и 21 о cache policy и общих security headers остаются следующими отдельными изменениями.

На Windows использован прежний SWC_NATIVE_BINDING_CACHE. Известное предупреждение Node о deprecated module.register относится к запуску development; браузерная консоль чистая.
