# Пункт 15: тайм-аут записи и удаления Redis

База: d57b5ba. Статус: реализовано, проверено и подтверждено пользователем 10 октября 2026 для отдельного коммита.

## Изменение

В RedisCache добавлен единый предел ожидания 1000 мс для SET, SET NX, SET IFEQ и DELEX IFEQ. При превышении лог содержит команду, предел и operation unconfirmed. Условная запись и удаление возвращают false; обычный SET завершает ожидание с прежним void-контрактом.

Таймер отменяется после завершения операции. Поздний результат не меняет возврат; Promise.race наблюдает позднюю ошибку. Проверка performance.now не позволяет принять просроченный результат после блокировки event loop. GET сохраняет отдельный REDIS_READ_TIMEOUT_MS.

Runtime-diff этого пункта ограничен src/server/services/cache/redis.cache.ts. Новые настройки env относятся к отдельному пункту 35.

## Предел гарантии

1000 мс ограничивают ожидание вызывающего кода. Отправленная Redis-команда может выполниться позже; неподтверждённый pending освобождается через TTL. Соединение не уничтожается, новый лимит числа незавершённых команд не вводится. Таймер не прерывает синхронную блокировку Node. Полный graceful shutdown остаётся пунктом 10.
