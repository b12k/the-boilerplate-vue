# Пункт 5: тайм-аут чтения Redis

Базовый коммит: 0475943. Реализация и проверки завершены 9 октября 2026. Пользователь подтвердил ревью и отдельный коммит 9 октября 2026. Коммит: 7601e14.

REDIS_READ_TIMEOUT_MS добавлен в Optional обоих env-файлов и в env-schema: положительное целое число миллисекунд, по умолчанию 1000. Через server и конфигурацию CacheService значение передаётся в RedisCache. RedisCache.get ограничивает ожидание этим бюджетом. Если ответ не пришёл, возвращается undefined — существующий контракт промаха; SSR продолжает работу. Ограничение действует и для render-cache, и для critical CSS, которые используют этот метод.

Тайм-аут логируется через существующий logger с причиной `[RedisCache] GET timed out after <REDIS_READ_TIMEOUT_MS> ms`, включая фактическое настроенное значение. После завершения чтения watchdog отменяется в finally. Promise.race обрабатывает поздние разрешения и отклонения Redis-команды; они не меняют выбранный результат. Тайм-аут чтения не вызывает destroy, reconnect или закрытие общего клиента.

Это предел ожидания ответа, а не отмена уже отправленного GET. Встроенный commandOptions.timeout node-redis ограничивает команды, ещё не записанные в socket, поэтому для ожидания ответа используется отдельный watchdog. [Документация node-redis](https://github.com/redis/node-redis/blob/master/docs/command-options.md).

Число подключений и разрывов proxy подтверждает отсутствие destroy/reconnect из-за тайм-аута.

## Границы пункта

REDIS_READ_TIMEOUT_MS — бюджет отдельного GET. Сейчас SSR читает render-cache и critical CSS последовательно, поэтому два тайм-аута добавляют два бюджета чтения плюс рендер; при default 1000 это около двух секунд. Тайм-аут подключения не изменён. Общий SSR response budget остаётся пунктом 8. Таймер Node может сработать позднее при блокировке event loop.

Предел ожидания SET/NX/EVAL относится к пункту 15. Отправленные команды могут продолжать ожидать ответ в клиенте Redis после завершения HTTP; этот пункт не вводит лимит таких команд.

Тестовые контейнеры удалены; dev восстановлен. Fixtures и результаты находятся в папке артефактов: redis-proxy-5.mjs, redis-read-probe-5.mjs, check-redis-read-5.mjs, check-read-env-5.mjs, fix-5-redis-read.json, fix-5-redis-read-config.json, fix-5-read-env-source/dist.json и recheck-fix-5-env-dev/local/docker.json. Windows использует отдельный SWC cache root процесса агента без изменения настроек проекта.
