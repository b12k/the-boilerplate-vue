# Пункт 7: Redis — единственный backend серверного кеша

Базовый коммит: e13e765. Пользователь подтвердил ревью и отдельный коммит 9 октября 2026.

Удалены LruCache, fallback и прямая зависимость lru-cache. CacheService использует один Redis-клиент для render и critical CSS с разными пространствами ключей. Без доступного клиента чтение даёт промах, записи пропускаются, pending не захватывается. Заголовок X-Cache: R появляется только при фактическом попадании в кеш.

REDIS_HOST, REDIS_PORT и REDIS_PASSWORD — обязательные параметры в схеме и секции Required обоих env-файлов. REDIS_URL вычисляется в env.ts; отдельного входного URL и условного refine больше нет. Пароль кодируется для URL, пустая строка означает Redis без авторизации. При отключении обоих кешей параметры конфигурации сохраняются, но подключение не выполняется.

## Границы изменения

lru-cache остаётся транзитивной зависимостью shrink-ray-current. Она не используется нашим render/critical CSS кешем; прямой зависимости приложения в package.json и importer lockfile больше нет.

Политика повторного подключения не изменена: первая неудачная попытка позволяет запустить HTTP, после разрыва установленного соединения действует существующий reconnect. Ограничение попыток — отдельный пункт 4; предел ожидания Redis-команд — пункты 5 и 15. Этот пункт не гарантирует тайм-аут для подключённого, но зависшего Redis.

Тестовые приложения и отдельный Redis удалены; образ сохранён. Dev восстановлен на localhost:8080. Для Windows использован отдельный SWC cache root процесса агента без изменения конфигурации проекта.

Сценарии и результаты находятся в папке артефактов: check-redis-only-7.mjs, check-redis-env-7.mjs, fix-7-redis-only.json, fix-7-env-source/dist.json и recheck-fix-7-dev/local/docker.json.
