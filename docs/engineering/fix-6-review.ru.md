# Пункт 6: SSR assets в памяти

Базовый коммит: 7601e14. Реализация и проверки завершены 9 октября 2026. Пользователь подтвердил ревью и отдельный коммит 9 октября 2026. Коммит: 48c9130.

Изменения production-кода ограничены `src/server/services/ssr-assets.service.ts`.

В production первая загрузка сохраняет Promise с manifest/render. Одновременные вызовы используют ту же загрузку; после успеха все получают один snapshot. Клиентский manifest читается один раз на процесс. SSR manifest нужен только для development decache и больше не читается в production.

При ошибке сохранённый Promise сбрасывается, и следующий вызов повторяет загрузку. Сброс проверяет принадлежность Promise: обработчик старой ошибки не может удалить новую попытку. Ошибка текущего вызова передаётся существующему middleware.

В development snapshot не сохраняется. Каждый вызов читает manifests и очищает CommonJS-кеш renderer и файлов из SSR manifest, как до изменения.

## Границы пункта

Production assets считаются неизменяемыми в течение жизни процесса. Новый релиз или обновление файлов требует перезапуска процесса. Каждый инстанс хранит собственный snapshot.

Предварительная загрузка при старте остаётся пунктом 10. Проверки формы manifest не добавлены. Ошибка первоначальной загрузки не превращается в постоянную ошибку кеша, но текущий HTTP-запрос сохраняет прежнюю обработку ошибки.

Тестовые контейнеры удалены; dev восстановлен. Windows использует отдельный SWC cache root процесса агента без изменения настроек проекта.
